## Purpose

The editor service (this repo, AGPL, an HTTP peer of every Monolith product) has to become what UDOC's document mode needs: the latest OnlyOffice Community, named editor profiles, stateless per-open sessions in sealed editor URLs, signed and retried consumer notifications, a drop command, PDF conversion, logs that never carry an access-granting URL, a product-agnostic panel bridge plugin, and hosting where its consumers run.

## Numbering rule

Phase EDIT-*n* implements parent step UDOC-1.*n* (EDIT-1 ↔ UDOC-1.1 … EDIT-7 ↔ UDOC-1.7). EDIT-0 is this initiative's own charter. A sub-step `EDIT-2.3` is the third sub-step of UDOC-1.2. Report progress upward in parent terms ("UDOC-1.2 done") and keep the parent plan's status in step with this one.

## Authority

The parent's decisions govern this initiative and are **not** re-decided here: D2 (OnlyOffice Community, latest release, AGPL peer), D7 (OnlyOffice renders edited documents), D11 (field-control conventions and the loose `contentLocked` lock), D13 (profiles, stateless per-open sessions, the key format, one editor at a time, the closing sequence, signed notifications), D14 (the panel bridge, origin rules, the panel token), and the parent's Risks section's fallbacks. Where code reality disagrees with the parent, record it here, raise it in the parent's handoff, and amend the parent before building against the disagreement. The local decisions below cover only what the parent leaves to the implementing repo.

## What exists today (verified 2026-10-16)

- `apps/api/src/routes/documents.ts` (430 lines): `POST /api/documents/open` (`fileUrl`, optional per-request `callbackUrl` checked against the consumer's `allowedCallbackDomains`, `fileName`, `user`, `permissions` limited to `edit`/`download`/`print`, optional `saveTo` GCS write-back); a random UUID document key; an **in-memory session map** (`:84`) with TTL cleanup; `GET /editor/:key` serving an HTML page that interpolates the title and config unescaped (`:413`, `:424`); `POST /api/documents/callback` (JWT check skipped when `ONLYOFFICE_JWT_SECRET` is unset or `secret`, `:195-197`), which forwards an **unsigned** POST to the consumer (`:250-258`); `GET /api/documents/:key/download` and `GET /api/sessions`, both reading the map.
- `apps/api/src/routes/files.ts`: `POST /api/files/upload` (local `/tmp` storage, extension allowlist, no magic-byte check — an open `ERRORS.md` entry outside UDOC) and `GET /api/files/:filename`.
- `apps/api/src/consumers.ts` / `auth.ts`: consumers authenticate by API key (dev only), HMAC, or JWKS, and are hostname-bound; `findConsumersByHostname` falls back to unbound consumers.
- `apps/api/src/storage.ts`: `validateSourceUrl` (`:75`; https only, private/loopback/link-local/metadata refused), `resolveDownloadUrl`, `generateUploadUrl`, `transferToGcs`.
- `apps/api/src/config.ts` is meant to be the only env reader but is not: `consumers.ts:87,92,106`, `server.ts:27,31`, and `files.ts:36-37` also read `process.env` (folded into `config.ts` at EDIT-2.1). `ONLYOFFICE_JWT_SECRET` defaults to `secret`. Strictness keys only on `NODE_ENV === 'production'`; the deployed dev editor runs `NODE_ENV=development`.
- **Callback trust (defect, `ERRORS.md` 2026-10-16 09:20):** the editor page embeds a config JWT signed with `ONLYOFFICE_JWT_SECRET` (`documents.ts:182`), and the callback route accepts any token that verifies under that secret and then trusts the body's `key`, `status`, and `url` (`:194-217`), so whoever holds an editor URL can forge a save.
- **File URL trust (defect, `ERRORS.md` 2026-10-16 09:20):** `resolveDownloadUrl` (`storage.ts:109-125`) passes any http(s) URL and signs a bare `bucket/object` with the service's own GCS identity; `saveTo` writes to any bucket; `validateSourceUrl` (`:75`, not exported) is pattern-only and skipped for URLs containing `://api:` or `://onlyoffice`.
- **Serving and framing:** consumer hostnames (`connect.`, `crm.monolithdocs.com`) reach the API through Cloudflare Tunnel; `app.monolithdocs.com` reaches nginx, whose `location /` proxies to DocumentServer. Non-`/api` paths other than `/editor/` get `X-Frame-Options: SAMEORIGIN` (`app.ts:57-59`); the consumer-auth public-path allowlist is in `auth.ts:69-82`; the rate limiter is 100/min per IP without `trustProxy`; the API Dockerfile copies `apps/api` and `packages/db` only; Fastify's `maxParamLength` is the default 100.
- The legacy upload answers `fileUrl` as `<API_INTERNAL_URL>/api/files/<id><ext>` (`files.ts:84`), an internal http URL.
- `docker-compose.yml`: `onlyoffice/documentserver:8.3`.
- `apps/web` and `packages/db` (Prisma) are scaffolds from `standalone-app` Phase 0 with no runtime use; D13 adds **no** database, so neither is used by this initiative.
- `docs/spikes/2026-10-contract-sections.md` (untracked): the 2026-10-15/16 spike on 9.4 / 10.0 / 8.3. Its harness was torn down.
- **No hosted editor exists (found 2026-10-17).** Project `monolith-docs` has no VM or reserved IP; both VMs were stopped around April and deleted on 2026-06-12 to stop spend (`deploy-pipeline-parity/plan.md`, Phase 4 note), with final snapshots kept. `connect.` and `crm.monolithdocs.com` answer Cloudflare 530 (no tunnel connector); `app.` times out. Every consumer flow below is therefore down today.
- **Callers of the legacy open shape** (their code checked 2026-10-16; the service they call is down, see above): `fastmail-connect` (`billing/packages/api/src/routes/docs-proxy.ts:197-233`: upload, then open with `permissions.edit = false`, no `callbackUrl`) and the Monolith Connect browser extension (`monolith-connect/apps/extension/src/lib/docs-api.ts:43-77`: upload, then open with default permissions, i.e. editable, no `callbackUrl`). Neither calls `/api/documents/:key/download`, `/api/sessions`, or sends `saveTo`. Monolith CRM has no editor integration.

## Constraints

- **Licence boundary:** this repo stays AGPL. No `@monolith-platform/*` or other proprietary package anywhere in it, including the plugin; proprietary panel UI lives in each consumer's own page (D14).
- **No database and no permanent document storage** (D13; CLAUDE.md). Conversion keeps neither file (UDOC-1.3).
- **Product-agnostic:** no CRM, Docs, or field semantics in the service or the plugin; `field:`/`block:` controls are created by tag and lock as the consumer asks, and their meaning stays with the consumer.
- **Contract-first:** UDOC-2.1 (`contracts-draft/document-editing.md` in Platform) is drafted alongside EDIT-2 and EDIT-5. The consumer guide (`docs/guides/consumer-integration.md`) is the implementation reference and must agree with the contract draft at each checkpoint; a disagreement stops the checkpoint until one of them is corrected.
- **Never fake success** around callbacks, notifications, conversion uploads, or signed URLs (CLAUDE.md).
- `apps/api/src/config.ts` becomes the only `process.env` reader at EDIT-2.1 (see "What exists today").

## Risks

- **Unproven OnlyOffice behaviour** (parent Risks): `contentLocked` behaviour, a plugin creating a tagged locked control (also under `modifyContentControl:false` and track changes), per-session plugin data, a page inside the plugin panel, ConvertService with tracked changes and comments, DocumentServer callback retries, the command service's drop, and a Word desktop round trip. Fallbacks are the parent's: a plugin that cannot insert a control inserts a marked plain-text placeholder converted by the consumer at the next save; a page that cannot run in the panel becomes the plugin calling the consumer API under CORS. Any other failure stops EDIT and reopens D2 in the parent.
- **Word desktop round trip** needs a Windows or macOS machine with Word; this dev box has neither. The parent's acceptance requires its output, so EDIT-1 cannot close with it blocked unless Josh waives it in writing (recorded in the plan).
- **Notification loss horizon:** without a database, a final save the consumer never acknowledges survives only as long as DocumentServer retries and keeps forgotten files (E6); the consumer guide states the measured horizon.
- **Deploy drains sessions:** sessions open at a deploy lose their in-memory state today and lose their old-format key at the EDIT-2 deploy; each deploy waits for open editors to drain (by DocumentServer's connection statistics if EDIT-1.5 proves them, otherwise in an announced maintenance window).
- **Breaking existing consumers:** E1 keeps `fastmail-connect` and the Connect extension's request shape working for when the service is stood up again (both are down today with the host); EDIT-2's acceptance replays both shapes in the battery.
- **Hosting:** no editor host exists at all since 2026-06-12. DOC-DPP is still in planning (its Phase 4 needs revising to a from-scratch stand-up) and blocked on Platform's DPP Phase 5; EDIT-6 is a full stand-up and cannot close until an editor host reachable from `crm-dev` exists. The proven path (GCE + Cloudflare Tunnel) remains the fallback.
- **AGPL additional terms on 9.4+** (attribution and labelling for modified versions): EDIT-1's ADR records that the image is shipped unmodified and that the plugin is ours, served separately.
- **Memory on altus-labs-dev:** DocumentServer plus Playwright is heavy; check `~/bin/heavy` before a battery run and run one at a time.
